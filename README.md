# Agent Zero

Agent Zero is a WhatsApp verification assistant built with Node.js, Twilio, Supabase, and optional Gemini multimodal review.

## Capabilities

- Chat about claims and get concise, uncertainty-aware answers.
- Match text claims against a Supabase fact-check database.
- Review links with Google Search grounding when Gemini is configured.
- Inspect Twilio-hosted image, video, and audio attachments with Gemini.
- Flag basic URL-format risks without opening user-supplied links.
- Return a WhatsApp-ready report with references and limitations.

AI-generated-content and deepfake judgements are not forensic proof. Without Gemini configured, the service does not pretend to analyze media: it reports that review is unavailable. Link checks are heuristic and do not establish whether a site is trustworthy.

## Requirements and configuration

- Node.js 20 or newer
- A Twilio WhatsApp sender and webhook
- A Supabase project for known-claim matching
- A Gemini API key for conversational, search-grounded, and multimodal review

Create `.env` in the project root:

```env
PORT=3000

# Supabase
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# Twilio
TWILIO_ACCOUNT_SID=your-account-sid
TWILIO_AUTH_TOKEN=your-auth-token
# Exact public HTTPS URL configured as the Twilio incoming-message webhook
PUBLIC_WEBHOOK_URL=https://your-domain.example/webhook/whatsapp

# Optional AI review
GEMINI_API_KEY=your-gemini-api-key
GEMINI_MODEL=gemini-2.5-flash
```

The server also accepts `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` as fallbacks. A publishable key may require suitable Supabase function permissions; use a server-only key with appropriate access for production. Never expose or commit a service-role/secret key. Forwarded message text and supported media are sent to Google for review when `GEMINI_API_KEY` is configured; disclose this to users and follow applicable privacy and retention requirements.

## Supabase setup

Run this SQL in the Supabase SQL editor:

```sql
create extension if not exists vector;

create table if not exists public.fact_checks (
  id bigint generated by default as identity primary key,
  claim text not null,
  verdict text not null,
  source_url text not null,
  embedding vector(384) not null
);

create or replace function public.match_fact_checks(
  query_embedding vector(384),
  similarity_threshold float,
  match_count int
)
returns table (
  claim text,
  verdict text,
  source_url text,
  similarity float
)
language sql
stable
as $$
  select
    fact_checks.claim,
    fact_checks.verdict,
    fact_checks.source_url,
    1 - (fact_checks.embedding <=> query_embedding) as similarity
  from public.fact_checks
  where 1 - (fact_checks.embedding <=> query_embedding) >= similarity_threshold
  order by fact_checks.embedding <=> query_embedding
  limit match_count;
$$;
```

## Install, test, and run

```powershell
npm install
npm test
npm start
```

The webhook listens on `http://localhost:3000/webhook/whatsapp`; `GET /health` reports whether Supabase and Gemini credentials are configured, not whether those external services are reachable. Set `PUBLIC_WEBHOOK_URL` to the exact public URL registered with Twilio. When `TWILIO_AUTH_TOKEN` is set, the webhook validates Twilio request signatures. Attachments are downloaded only over HTTPS from approved Twilio media resources, require the Twilio account SID and auth token, and are limited to 8 MB each, 12 MB combined, and three per message.

Supported attachment types include JPEG, PNG, WebP, GIF, MP4, WebM, QuickTime video, and common audio formats. Media review requires both Gemini and Twilio credentials. The first database claim match downloads the `Xenova/all-MiniLM-L6-v2` embedding model.
